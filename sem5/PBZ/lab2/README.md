# Учёт договоров страхования

Лабораторная работа № 2, вариант 9. Настольное приложение для учёта коллективных и индивидуальных договоров страхования, сотрудников организаций, страховых агентов, сумм по категориям риска и страховых случаев.

Приложение написано на Python. Данные хранятся в SQLite, интерфейс построен с помощью Tkinter и `ttk`. Дополнительные библиотеки из `pip` для работы приложения не нужны.

## Запуск

Нужен Python 3.10 или новее с поддержкой Tkinter и доступным графическим окружением. На Ubuntu и Linux Mint системный пакет Tkinter можно установить командой:

```bash
sudo apt install python3-tk
```

Проверить наличие Tkinter именно у используемого интерпретатора:

```bash
python3 -c "import sys, tkinter; print(sys.executable); print(tkinter.TkVersion)"
```

Если пакет установлен, но импорт не работает, проверьте путь, который выводит `python3`, и используемое виртуальное окружение: системный пакет может относиться к другому интерпретатору Python.

Запуск из каталога проекта:

```bash
python3 main.py
```

При первом запуске приложение создаёт отсутствующие таблицы, индексы и триггеры. По умолчанию используется файл `data/insurance.db`. База сохраняется между запусками; при обычном запуске записи не очищаются.

Чтобы использовать другой файл базы, задайте переменную окружения:

```bash
INSURANCE_DB_PATH=/путь/к/insurance.db python3 main.py
```

Параметр `python3 main.py --console` оставлен для совместимости, но консольный режим отключён: приложение предлагает войти через графический интерфейс. Прямой запуск `python3 cli.py` также выводит приглашение использовать графическое приложение.

## Вход и регистрация

Сначала открывается окно с названием страховой компании и паролем. Здесь же можно зарегистрировать новую страховую компанию: введите название, пароль `1234` и нажмите «Зарегистрироваться». После регистрации сразу открывается кабинет компании. Для последующих входов используйте то же название и пароль.

В общем демонстрационном наборе встречаются следующие страховые компании:

| Название компании — логин | Пароль |
| --- | --- |
| `БелСтрах` | `1234` |
| `Надёжный полис` | `1234` |
| `Защита` | `1234` |

В новой пустой базе эти компании автоматически не создаются. Чтобы войти под одним из этих названий, сначала зарегистрируйте его или загрузите общий демонстрационный набор, описанный ниже. Для любой другой зарегистрированной компании логином служит введённое при регистрации название, а паролем — `1234`.

Кнопка **«Выйти из учётной записи»** закрывает кабинет и возвращает к окну входа. Там можно войти под другой страховой компанией.

**Ограничение безопасности:** авторизация и разделение данных сделаны для учебного проекта. Пароль одинаков для всех компаний и не хранится отдельно для каждой учётной записи. Любой человек, знающий название компании и общий пароль, может войти в её кабинет; также локальный пользователь может напрямую открыть файл SQLite. Приложение не предназначено для хранения конфиденциальных реальных данных.

## Работа с приложением

После входа открывается кабинет выбранной страховой компании. Записи в таблицах можно выбирать мышью; кнопки над таблицей выполняют соответствующие действия. Для удаления требуется подтверждение. В таблицах предусмотрены вертикальная и горизонтальная прокрутки, а ширину столбцов можно изменять вручную.

Важно различать **страховую компанию**, под которой выполнен вход, и **организацию-страхователя**, сотрудники которой включаются в коллективный договор.

### Организации

Во вкладке «Организации» можно добавлять, изменять и удалять организации-страхователи. Указываются код, полное и краткое названия, адрес, банковские реквизиты и специализация. Код должен быть положительным целым числом и уникальным в базе.

Новую организацию можно добавить ещё до создания договора: она привязывается к текущей страховой компании и появляется в форме договора. Организацию, связанную с сотрудниками или договорами, удалить нельзя. Если запись уже используется другой страховой компанией, её изменение и удаление запрещены, чтобы не затронуть данные другого кабинета.

### Сотрудники

Во вкладке «Сотрудники» добавляются, изменяются и удаляются страхуемые сотрудники. Для сотрудника выбирается доступная текущей компании организация, затем вводятся ФИО, возраст и категория риска. Организация сотрудника после создания не изменяется.

Сотрудника можно добавить до заключения договора. Если он включён в договор, удалить его нельзя. При изменении категории проверяются суммы во всех его договорах и уже сохранённые страховые случаи. Запись, используемую другой страховой компанией, изменить или удалить нельзя.

### Агенты

Во вкладке «Агенты» ведутся ФИО, паспортные данные, телефон и название страховой компании агента. При работе в кабинете название текущей компании подставляется автоматически. Агент с действующими или завершёнными договорами защищён связями базы от удаления, пока эти договоры существуют.

### Физические лица

Во вкладке «Физические лица» ведутся индивидуальные договоры: номер, ФИО страхователя, агент, даты начала и окончания и страховая сумма. Номер договора проверяется на уникальность и среди индивидуальных, и среди коллективных договоров. Отдельные страховые случаи по индивидуальным договорам в текущей версии не ведутся.

### Коллективные договоры

Во вкладке «Договоры» доступны создание, изменение, удаление и поиск по номеру. При создании выбираются организация, агент и один или несколько сотрудников этой организации. Для каждой категории выбранных сотрудников указывается сумма по договору, по одной категории на строку:

```text
первая = 10000.00
вторая = 15000.00
высшая = 20000.00
```

Организация договора после создания не изменяется. Сам договор, список сотрудников и суммы по категориям сохраняются одной транзакцией: при ошибке изменения откатываются. Если по договору уже есть страховые случаи, изменить состав, даты или суммы так, чтобы они противоречили этим случаям, нельзя. Перед удалением договора необходимо удалить связанные страховые случаи.

### Страховые случаи

Во вкладке «Страховые случаи» указываются коллективный договор, включённый в него сотрудник, дата, сумма и описание. Дата должна находиться в пределах действия договора, а сумма не должна превышать сумму для категории сотрудника. При выборе договора список сотрудников ограничивается его составом.

В этой модели дата страхового случая используется как дата выплаты; отдельного поля даты выплаты нет.

## Отчёты

Во вкладке «Отчёты» вводится дата в формате `YYYY-MM-DD`. Код организации-страхователя необязателен: если его указать, данные ограничиваются этой организацией. Во всех случаях учитываются договоры текущей страховой компании. Договор считается действующим, если выбранная дата находится между датами его начала и окончания включительно.

| Кнопка | Содержимое отчёта |
| --- | --- |
| «Договоры» | Организация, адрес, номер договора, даты начала и окончания действующего договора. |
| «Агенты» | Страховая компания, ФИО и телефон агентов, ведущих действующие договоры на выбранную дату. |
| «Суммы по категориям» | Организация, договор, категория риска, предусмотренная сумма и период действия договора. |

В отчёте по суммам показаны **условия договоров по категориям**, а не сумма фактических страховых случаев. Одинаковые категории в разных договорах выводятся отдельными строками. Для договоров и сумм отображается период, в течение которого они актуальны.

## Демонстрационные данные

### Данные текущей компании

После входа кнопка **«Заполнить данные компании»** добавляет примеры для выбранного страховщика: организации, сотрудников, агентов, коллективные и индивидуальные договоры, суммы по категориям и страховые случаи. В окне результата показано количество добавленных записей каждого типа.

При повторном заполнении уже существующие подходящие примеры не дублируются. Если существующая запись конфликтует с ожидаемым примером, часть данных может быть пропущена. Названия организаций создаются без приписки названия страховой компании.

### Общий набор для разработки и тестов

Функция `seed_database()` из `models/seed.py` создаёт общий набор для нескольких компаний; дополнение этого набора находится в `models/demo_data.py`. Это отдельный механизм, который **не запускается** кнопкой заполнения текущей компании. При необходимости его можно вызвать вручную из корня проекта:

```bash
python3 -c "from models.seed import seed_database; print(seed_database())"
```

Команда записывает данные в выбранную базу и не очищает её. Она предназначена для разработки и тестирования, поэтому при работе со своей базой сначала решите, нужны ли в ней общие примеры. Для отчётов по базовой части набора можно войти под `БелСтрах`, указать код организации `9001` и дату `2026-11-03`: на эту дату действуют договоры `КД-0001` и `КД-0002`.

### Обновление старых примеров

При инициализации `models/format_migration.py` распознаёт некоторые старые форматы демонстрационных номеров, паспортов и банковских реквизитов, нормализует подходящие телефонные номера и убирает из конца названия организации приписку вида ` (название страховой компании)`, если название компании известно базе. Другие окончания в скобках не удаляются только из-за наличия скобок.

Если найдены изменения, перед ними создаётся резервная копия рядом с базой: `insurance.before-format-<время>.db` для базы с именем `insurance.db`. Сами записи и их идентификаторы сохраняются.

## Очистка данных и идентификаторы

Кнопка **«Очистить данные компании»** удаляет данные текущего страховщика, в том числе введённые вручную. Сначала приложение показывает предупреждение, затем просит ввести фразу `УДАЛИТЬ ВСЁ`. Учётная запись остаётся, чтобы в неё можно было войти снова.

Договоры, страховые случаи, индивидуальные договоры и агенты текущей компании удаляются. Общие записи, необходимые другим страховым компаниям, сохраняются. Организации и сотрудники, которые больше ни с чем не связаны и не принадлежат другим страховщикам, удаляются вместе с данными текущей компании.

ID в некоторых таблицах создаются с помощью SQLite `AUTOINCREMENT`. Их счётчики сбрасываются только для полностью пустых соответствующих таблиц. Если в таблице остаются записи других компаний, счётчик остаётся общим: после повторного заполнения ID не обязательно начнутся с `1`.

Функция `clear_database()` в `models/database.py` очищает **всю** базу, включая учётные записи. Кнопка в кабинете её не вызывает. Функция используется в том числе для тестов; вручную вызывать её следует только при необходимости полной очистки.

## Проверка вводимых данных

- **Текст:** обязательные поля проверяются на пустоту, лишние пробелы сводятся к одиночным. Новые текстовые значения с `DEMO` не принимаются.
- **Телефон агента:** принимается белорусский номер с допустимыми разделителями; сохраняется в виде `+375XXXXXXXXX`.
- **Дата:** формат `YYYY-MM-DD`, например `2026-11-03`. Проверяется существование календарной даты и порядок начала и окончания договора.
- **Суммы:** неотрицательные значения с точностью не более двух знаков после запятой. Проверки выполняются с `Decimal`.
- **Возраст, код организации и ID связанных записей:** положительные целые числа там, где их требует модель.
- **Связи:** сотрудник договора должен принадлежать выбранной организации, а для каждой категории выбранных сотрудников должна быть задана сумма. Сумма случая не может превышать сумму его категории в договоре.

Нормализация применяется при сохранении новых и изменяемых данных; произвольные старые записи не проходят полную автоматическую проверку при запуске.

## Устройство базы данных

Подключение создаётся через `models/database.py`; для него включены внешние ключи SQLite (`PRAGMA foreign_keys = ON`). В таблицах используются первичные ключи `id`, кроме таблиц связей и списка страховых компаний.

| Таблица | Содержимое и связи |
| --- | --- |
| `InsuranceCompany` | Названия зарегистрированных страховых компаний. Название используется как ключ и логин. |
| `Organization` | Организации-страхователи: код, названия, адрес, реквизиты и специализация. |
| `Employee` | Сотрудники организаций, их возраст и категория риска; `organization_id` ссылается на `Organization`. |
| `Agent` | Агенты, их паспортные данные, телефоны и название страховой компании. |
| `Contract` | Коллективные договоры; каждый ссылается на одну организацию и одного агента, содержит номер и период действия. |
| `ContractEmployee` | Связь договоров и сотрудников. Один договор может включать нескольких сотрудников, а сотрудник — входить в несколько договоров. Пара `contract_id`, `employee_id` уникальна. |
| `Payout` | Предусмотренные договором суммы по категориям риска. Для каждой пары договора и категории хранится одна сумма. |
| `IndividualContract` | Индивидуальные договоры физлиц с привязкой к агенту. |
| `InsuranceClaim` | Страховые случаи по коллективному договору и конкретному сотруднику: дата, сумма и описание. |
| `InsurerOrganization` | Связь страховщика с доступной ему организацией, в том числе созданной до первого договора. |
| `InsurerEmployee` | Связь страховщика с доступным ему сотрудником, в том числе созданным до первого договора. |

При инициализации связи страховщика с организациями и сотрудниками дополняются по уже существующим коллективным договорам. В видимость кабинета также входят записи, связанные через договоры агентов компании. На уровне SQLite хранятся одни и те же общие записи организаций и сотрудников, поэтому общую запись нельзя изменить или удалить из одного кабинета, если она используется другим страховщиком.

`transaction()` в `models/database.py` открывает транзакцию и выполняет `commit` при успехе или `rollback` при исключении. Это применяется, например, при сохранении договора со списком сотрудников и суммами, а также при очистке данных.

## Триггеры

Триггеры создаются при инициализации базы и дополняют проверки Python:

- `contract_employee_org_insert` и `contract_employee_org_update` не позволяют включить в договор сотрудника другой организации.
- `employee_organization_update` и `contract_organization_update` не позволяют изменить организацию так, чтобы уже сохранённые связи договора с сотрудниками стали противоречивыми.
- `contract_date_order_insert`, `contract_date_order_update`, `individualcontract_date_order_insert` и `individualcontract_date_order_update` запрещают окончание договора раньше начала.
- `agent_company_update` запрещает менять страховую компанию агента, если за ним закреплены коллективные или индивидуальные договоры.

Триггеры проверяют новые операции и не исправляют автоматически старые некорректные строки. Проверка формата и существования календарной даты выполняется в Python.

```text
├── tests/                     # автоматические тесты
└── data/                      # файл SQLite и возможные резервные копии
```

### Точка входа и интерфейс

- **`main.py`** разбирает аргументы запуска, вызывает `init_database()`, загружает Tkinter и запускает `Login` и `App`. Функция `run_sessions()` повторно открывает окно входа после выхода из учётной записи.
- **`ui/app.py`** содержит классы `Login` и `App`. Здесь создаются формы, вкладки, таблицы `ttk.Treeview`, кнопки, окна подтверждения, отчёты и обработчики действий. Для операций интерфейс обращается к `Tenant`, моделям и вспомогательным функциям.
- **`cli.py`** содержит описание полей `FIELDS`, соответствие разделов моделям и функции `save_item()` / `delete_item()`, которые использует GUI для агентов и индивидуальных договоров. В файле также осталось прежнее консольное меню для работы с моделями; штатный запуск этого меню отключён, поскольку оно не выполняет разделение по страховым компаниям.

### Модели и база

- **`models/database.py`** определяет `get_connection()`, создание схемы и индексов в `init_database()`, создание триггеров в `init_triggers()`, контекстный менеджер `transaction()`, чтение строк через `records()` и полную очистку через `clear_database()`.
- **`models/tenant.py`** проверяет вход и регистрацию. Объект `Tenant` хранит название текущей страховой компании, выбирает её данные, проверяет принадлежность записей, управляет доступными организациями и сотрудниками, строит отчёты и очищает данные компании. GUI использует этот модуль для разделения кабинетов.
- **`models/organization.py`** содержит класс `Organization`: чтение, проверку, добавление, изменение и удаление организаций. Проверяет, что перед удалением организация не связана с сотрудниками или договорами.
- **`models/employee.py`** содержит класс `Employee` и операции с сотрудниками. При изменении категории проверяет связанные договоры и страховые случаи; при удалении проверяет включение в договор.
- **`models/agent.py`** содержит класс `Agent` и операции с агентами. Использует общую проверку текста и телефона, проверяет повтор паспортных данных.
- **`models/contract.py`** содержит класс `Contract`: поля коллективного договора, проверку дат, операции с сотрудниками договора, сохранение договора вместе с категориями и суммы для отчётов. `save_contract()` используется формой договора, `delete_contract()` проверяет отсутствие связанных случаев. В модуле также остались методы отчётов без фильтрации по кабинету; GUI строит отчёты через `Tenant`.
- **`models/payout.py`** содержит модель `Payout` для сумм по категориям и функцию `money()` для проверки и форматирования денежных значений. `money()` используется при сохранении договоров и страховых случаев.
- **`models/individual_contract.py`** содержит операции `IndividualContract` с индивидуальными договорами. Проверяет номера, даты, агента и сумму; вызывается через общие функции из `cli.py`.
- **`models/insurance_claim.py`** содержит `InsuranceClaim.save_claim()` и `delete_claim()`. При сохранении проверяет сотрудника, период договора и допустимую сумму.
- **`models/validation.py`** предоставляет `required_text()` для текстовых полей и `phone_number()` для телефонов. Ими пользуются модели, работающие с соответствующим вводом.
- **`models/__init__.py`** и **`ui/__init__.py`** обозначают каталоги как пакеты Python; отдельной прикладной логики в них нет.

### Демонстрационные данные и обновление форматов

- **`models/company_seed.py`** содержит `seed_company(company)`. Её вызывает кнопка в кабинете: функция добавляет набор для конкретной страховой компании и возвращает счётчики добавленных записей.
- **`models/seed.py`** содержит исходные небольшие наборы организаций, агентов, сотрудников и договоров и функцию `seed_database()`. Она применяется для общего демонстрационного набора и в тестах.
- **`models/demo_data.py`** дополняет общий набор более крупными примерами. Функция `add_supplemental_data()` вызывается из `seed_database()`.
- **`models/format_migration.py`** вызывается из `init_database()`. Модуль находит поддерживаемые старые значения, при необходимости сохраняет копию базы и обновляет эти значения.

### Тесты

- **`tests/test_app.py`** — модели, CRUD, транзакции, отчёты и поведение точек запуска.
- **`tests/test_company_seed.py`** — заполнение данных компании, вход и выход, очистка и обновление названий организаций.
- **`tests/test_demo_clear.py`** — общий демонстрационный набор, повторное заполнение и очистка базы.
- **`tests/test_tenant.py`** — авторизация, разделение данных, организации и сотрудники компании, отчёты и обновление старых форматов.
- **`tests/test_triggers.py`** — проверки триггеров SQLite и совместимости операций моделей с ними.
- **`tests/test_table_layout.py`** — расчёт высоты строк и ширины столбцов таблиц.

## Как взаимодействуют модули

При запуске `main.py` вызывает `models.database.init_database()`: создаются недостающие таблицы, индексы и триггеры, затем выполняется обновление поддерживаемых старых форматов. После этого открывается `Login` из `ui/app.py`.

При успешном входе `models.tenant.authenticate()` возвращает объект `Tenant` с названием страховой компании. `App` получает этот объект и использует его при отображении и проверке доступных записей. Например, при создании договора интерфейс получает организации, агентов и сотрудников текущей компании из `Tenant`, а затем передаёт выбранные данные в `Contract.save_contract()`. Метод проверяет данные и сохраняет связанные записи через транзакцию SQLite.

При открытии отчёта интерфейс передаёт дату и необязательный код организации в один из методов `Tenant.report_contracts()`, `report_agents()` или `report_payouts()`. Метод выполняет запрос с фильтром по текущему страховщику, после чего интерфейс отображает результат в таблице.

## Тестирование

Из каталога проекта:

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют временные базы и стандартный модуль `unittest`. Они проверяют модели, операции с данными, ограничения, отчёты, заполнение, очистку и триггеры. Тесты расчёта размеров таблиц используют подмены объектов; для полноценной визуальной проверки окон нужен графический дисплей.

## Ограничения

- Это учебное локальное приложение с общим паролем, а не система защиты реальных персональных данных.
- Категория риска задаётся текстом. Её написание в карточке сотрудника должно совпадать с категорией в суммах договора.
- Дата случая используется как дата выплаты. Отдельный учёт выплат по индивидуальным договорам не реализован.
- Сумма категории в таблице `Payout` хранится как SQLite `REAL`; при вводе значения проверяются через `Decimal`. Отчёт выводит суммы отдельно, без их суммирования.
- `CREATE TABLE IF NOT EXISTS` создаёт отсутствующие таблицы, но не перестраивает существующие таблицы при изменении их структуры. Перед ручным изменением схемы или переносом данных сделайте копию базы.
