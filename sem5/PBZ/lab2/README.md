# Учёт договоров страхования

Настольное приложение на Python и SQLite для лабораторной работы № 2, вариант 9. Графический интерфейс построен на Tkinter и ttk. Постановка задачи и описание схемы находятся в [docs/TASK.md](docs/TASK.md) и [docs/DESIGN.md](docs/DESIGN.md).

## Запуск

Нужен Python 3.10 или новее с Tkinter. В Ubuntu/Mint, если Tkinter отсутствует, установите `python3-tk`. Из каталога проекта:

```bash
python3 main.py
```

При запуске создаются недостающие таблицы базы `data/insurance.db`; существующие записи не удаляются. Чтобы использовать другую базу, задайте переменную `INSURANCE_DB_PATH`. Обновление существующих определений таблиц автоматически не выполняется; перед изменением схемы существующей базы сохраните её копию.

Для входа укажите название страховой компании и пароль `1234`. Чтобы создать компанию, введите её название и тот же учебный пароль и нажмите «Зарегистрироваться». После входа можно заполнить данные компании кнопкой в главном окне. Консольный режим с неограниченным просмотром отключён.

В стандартном наборе демонстрационных данных предусмотрены следующие страховые компании:

| Логин | Пароль |
|---|---|
| `БелСтрах` | `1234` |
| `Надёжный полис` | `1234` |
| `Защита` | `1234` |

Если база пуста, эти компании сначала нужно зарегистрировать. Для дополнительно зарегистрированной компании логином служит введённое название, пароль — `1234`.

После входа показываются только договоры, которые ведут агенты выбранной страховой компании, связанные организации, застрахованные сотрудники, страховые случаи и индивидуальные договоры. Организации и сотрудники доступны только для просмотра: эти записи могут использоваться в договорах других страховщиков. Управлять агентами своей страховой компании можно во вкладке «Агенты». Общая очистка базы из кабинета недоступна.

Кнопка «Заполнить данные компании» добавляет примеры только для текущей страховой компании. Повторное нажатие не дублирует эти примеры. Кнопка «Выйти из учётной записи» возвращает к окну входа. Кнопка «Очистить данные компании» после двух подтверждений удаляет данные текущего страховщика, сохраняя его учётную запись и записи, связанные с другими страховщиками. Для полностью пустых таблиц счётчики ID сбрасываются; при наличии других записей сбрасывать общий счётчик нельзя.

**Это учебная фильтрация, а не защита конфиденциальных данных:** пароль одинаковый для всех страховых компаний, поэтому любой знающий его может войти под другим названием. Файл SQLite также доступен локальному пользователю напрямую. Для реальной защиты нужны отдельные пароли и сервер, который проверяет права на каждую операцию.

При первом запуске после обновления распознанные старые демонстрационные номера и телефоны приводятся к новому формату. Перед изменением создаётся копия `data/insurance.before-format-*.db`. Произвольные пользовательские поля автоматически не переписываются.

## Работа с приложением

Вкладки позволяют управлять агентами, коллективными и индивидуальными договорами и страховыми случаями своей страховой компании, а также просматривать связанные организации и сотрудников. В таблице выберите запись и нужную операцию. Удаление требует подтверждения; связанные записи защищены от случайного удаления.

В форме коллективного договора выберите организацию, агента и сотрудников. Для каждой категории выбранных сотрудников укажите сумму в формате `категория = сумма`, по одной строке. Договор, состав сотрудников и суммы сохраняются одной транзакцией. Дата вводится как `YYYY-MM-DD`; день заключения считается началом действия, обе границы включены.

Во вкладке «Отчёты» введите дату и выберите вид отчёта. Код организации-страхователя можно указать дополнительно. Страховая компания определяется при входе. Суммы для одной категории выводятся отдельно по договорам.

Для демонстрации используйте организацию `9001` и дату `2026-11-03`: два действующих договора КД-0001 и КД-0002, один агент и пять сумм по категориям.

## Допущения

Организацию сотрудника или коллективного договора после создания изменить нельзя. Сумма категории — условие договора; фактический страховой случай хранится отдельно. Дата случая принимается за дату выплаты. В индивидуальном договоре хранятся ФИО страхователя, номер, агент, даты и сумма; отдельный страховой случай для него не предусмотрен.

Сумма категории в исходной схеме SQLite хранится как `REAL`. Ввод проверяется с помощью `Decimal`, отчёт показывает значения без сложения. Приложение предназначено для лабораторной работы.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Телефон при вводе приводится к виду `+375XXXXXXXXX`, даты — `YYYY-MM-DD`, денежные суммы проверяются с точностью до двух знаков. Пробелы в текстовых полях нормализуются; новые значения с `DEMO` отклоняются. Старые некорректные пользовательские значения не исправляются автоматически.

Тесты используют временные базы данных. Для визуальной проверки окна требуется доступный графический дисплей.
