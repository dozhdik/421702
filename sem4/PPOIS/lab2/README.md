## 1. Цель работы

Разработать настольное приложение с графическим интерфейсом для управления базой данных складских товаров. Приложение должно реализовывать архитектурный паттерн MVC с пассивной моделью, обеспечивать персистентность данных через XML-файлы, поддерживать операции добавления, поиска и удаления записей по составным критериям (Вариант 6), а также постраничную навигацию по набору данных.

## 2. Архитектура приложения

### 2.1 Паттерн MVC с пассивной моделью

Приложение построено на архитектурном паттерне **Model-View-Controller** в варианте с **пассивной моделью**: модель не знает о существовании представления и не инициирует его обновление. Обновление представления — исключительная ответственность контроллера.

```
┌─────────────┐   вызывает методы   ┌─────────────┐
│  Controller │ ──────────────────► │    Model    │
│             │ ◄────────────────── │             │
│             │   возвращает данные │             │
└──────┬──────┘                     └─────────────┘
       │ вызывает методы
       │ отображения
       ▼
┌─────────────┐   события/колбэки  ┌─────────────┐
│    View     │ ──────────────────► │  Controller │
└─────────────┘                     └─────────────┘
```

**Ключевое свойство пассивной модели:** `WarehouseModel` не содержит ссылок на `WarehouseView`. После каждой мутации данных контроллер явно вызывает `_refresh_display()`, который запрашивает актуальное состояние у модели и передаёт его в представление.

### 2.2 Разделение ответственности

| Компонент | Файл | Ответственность |
|-----------|------|-----------------|
| `WarehouseModel` | [model.py](warehouse_app/model.py) | Хранение записей, бизнес-логика поиска/удаления, валидация, XML I/O |
| `WarehouseView` | [view.py](warehouse_app/view.py) | Построение и обновление всех виджетов tkinter, диалоги, колбэки событий |
| `WarehouseController` | [controller.py](warehouse_app/controller.py) | Связывание модели и представления, управление пагинацией, обработка событий |
| `Record` | [model.py](warehouse_app/model.py) | Dataclass записи с методом `validate()` |
| Точка входа | [main.py](warehouse_app/main.py) | Создание `tk.Tk`, инстанцирование MVC-триады, запуск `mainloop` |

### 2.3 Взаимодействие компонентов

1. `main.py` создаёт `WarehouseModel`, `WarehouseView(root)`, `WarehouseController(model, view)`.
2. В конструкторе контроллер регистрирует колбэки через `view.set_callback(event_name, handler)`.
3. Пользователь взаимодействует с виджетами View; виджеты вызывают `_trigger_callback(event_name)`.
4. Контроллер получает управление, вызывает методы модели, затем вызывает `_refresh_display()`.
5. `_refresh_display()` получает данные из модели через `model.get_all_records()` и передаёт срез текущей страницы в `view.display_records(...)`.

## 3. Работа с данными

### 3.1 Структура записи

```python
@dataclass
class Record:
    product_name: str          # Название товара
    manufacturer_name: str     # Название производителя
    unp_manufacturer: str      # УНП (9 цифр)
    quantity_in_stock: Union[int, str]  # int >= 0 или "нет на складе"
    warehouse_address: str     # Адрес склада
```

Поле `quantity_in_stock` имеет **смешанный тип**: числовое значение (остаток) или строка `"нет на складе"`. Это отражает реальную семантику: отсутствие товара — не ноль, а особое состояние.

### 3.2 Валидация

Метод `Record.validate()` проверяет:
- `product_name`, `manufacturer_name`, `warehouse_address` — непустые строки после `strip()`;
- `unp_manufacturer` — только цифры (если не пустой);
- `quantity_in_stock` — либо `int >= 0`, либо строка `"нет на складе"`.

Валидация вызывается в `WarehouseModel.add_record()` до добавления записи в список. Диалог `AddRecordDialog` дублирует проверки на стороне UI для немедленной обратной связи.

### 3.3 Формат XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<warehouse_db>
    <record>
        <product_name>Дрель Bosch Professional GSB 13 RE</product_name>
        <manufacturer_name>Bosch GmbH</manufacturer_name>
        <unp_manufacturer>193567821</unp_manufacturer>
        <quantity_in_stock>45</quantity_in_stock>
        <warehouse_address>Минск, ул. Промышленная, 10</warehouse_address>
    </record>
    ...
</warehouse_db>
```

### 3.4 SAX vs DOM: выбор парсера

| Критерий | SAX (чтение) | DOM (запись) |
|----------|-------------|--------------|
| Модель работы | Потоковая, событийная | Дерево в памяти |
| Потребление памяти | O(1) — не строит дерево | O(n) — всё дерево в RAM |
| Удобство построения документа | Неудобно | Удобно: `createElement`, `appendChild` |
| Произвольный доступ к узлам | Нет | Да |
| Обоснование выбора | Эффективное чтение больших файлов | Удобное построение и форматирование (`toprettyxml`) |

**SAX-обработчик** `WarehouseSAXHandler` реализует три метода `ContentHandler`:
- `startElement` — инициализирует словарь текущей записи при теге `<record>`;
- `characters` — накапливает текстовое содержимое элемента;
- `endElement` — при закрытии `</record>` конструирует объект `Record` и добавляет в список.

**DOM-запись** в `save_to_xml` строит документ программно через `xml.dom.minidom.Document` и сохраняет с отступами через `toprettyxml(indent="    ", encoding="UTF-8")`.

## 4. Графический интерфейс и пагинация

### 4.1 Компоненты интерфейса

Главное окно (`WarehouseView`, 1400×750 px) состоит из пяти зон, размещённых менеджером геометрии `pack`:

| Зона | Виджеты | Описание |
|------|---------|----------|
| Меню | `tk.Menu` | Файл / Правка / Данные / Справка |
| Панель инструментов | `ttk.Frame` + `ttk.Button`, `ttk.Separator` | Быстрый доступ к основным операциям |
| Основная таблица | `ttk.Treeview` + `ttk.Scrollbar` (вертикальный и горизонтальный) | Отображение записей текущей страницы |
| Пагинация | `ttk.Button` (<<, <, >, >>), `ttk.Label`, `ttk.Spinbox` | Навигация по страницам, выбор размера страницы |
| Строка состояния | `ttk.Label` (relief=SUNKEN) | Текущий статус операции |

**Размещение виджетов в таблице** использует комбинацию `pack` (для фреймов) и `grid` (внутри `main_frame` для `Treeview` и полос прокрутки). Такой подход позволяет таблице растягиваться при изменении размера окна (`grid_rowconfigure(0, weight=1)`, `grid_columnconfigure(0, weight=1)`).

**Диалоги** (`AddRecordDialog`, `SearchDialog`, `DeleteDialog`) — модальные окна `tk.Toplevel` с `transient(parent)` и `grab_set()`. Они центрируются относительно родительского окна через `winfo_x/y/width/height`.

### 4.2 Алгоритм пагинации

Состояние пагинации хранится в контроллере (`current_page: int`) и представлении (`per_page_var: tk.StringVar`).

```
total_pages  = ceil(total_records / records_per_page)  # минимум 1
current_page = clamp(current_page, 1, total_pages)
start_idx    = (current_page - 1) * records_per_page
end_idx      = start_idx + records_per_page
page_records = all_records[start_idx:end_idx]
```

**Сброс на первую страницу** происходит при:
- добавлении записи (`_on_add`);
- удалении записей (`_on_delete`);
- загрузке файла (`_on_open`);
- создании новой БД (`_on_new`);
- генерации тестовых данных (`_on_generate_test_data`);
- изменении количества записей на странице (`_on_per_page_changed`).

`ttk.Spinbox` с диапазоном 1–100 позволяет задать произвольное количество записей на странице. Диалог поиска имеет собственную независимую пагинацию результатов (фиксированно 10 записей на страницу).

### 4.3 Автоматическое изменение ширины колонок

После каждого обновления таблицы вызывается `auto_resize_columns()`, который измеряет ширину каждой ячейки через `tkinter.font.Font.measure()` с коэффициентом 1.3 и устанавливает ширину колонки по максимальному значению.

## 5. Логика поиска и удаления (Вариант 6)

### 5.1 Структура условий

Критерии разбиты на три группы. Внутри группы условия объединяются через **OR**; группы между собой — через **AND**:

```
(product_name_match OR quantity_match)
AND
(manufacturer_match OR unp_match)
AND
(address_match)
```

Группа участвует в проверке только если хотя бы одно из её полей заполнено. Пустые группы не влияют на результат — запись проходит фильтр по умолчанию.

### 5.2 Детали сопоставления

| Поле | Тип сравнения | Регистр |
|------|--------------|---------|
| `product_name` | подстрока (`in`) | нечувствительный |
| `quantity_in_stock` | точное совпадение | — |
| `manufacturer_name` | подстрока (`in`) | нечувствительный |
| `unp_manufacturer` | подстрока (`in`) | — |
| `warehouse_address` | подстрока (`in`) | нечувствительный |

Для `quantity_in_stock`: если введено `"нет на складе"` — сравнивается со строкой; иначе строка парсится в `int` и сравнивается с числовым значением поля.

### 5.3 Реализация в коде

```python
# model.py — WarehouseModel.search_records()

# Группа 1: product_name OR quantity_in_stock
if product_name or quantity:
    product_match = product_name in record.product_name.lower()
    quantity_match = ...  # точное совпадение int или строки
    if not (product_match or quantity_match):
        match = False

# Группа 2: manufacturer_name OR unp_manufacturer
if manufacturer_name or unp:
    manufacturer_match = manufacturer_name in record.manufacturer_name.lower()
    unp_match = unp in record.unp_manufacturer
    if not (manufacturer_match or unp_match):
        match = False

# Группа 3: warehouse_address
if warehouse_address:
    if warehouse_address not in record.warehouse_address.lower():
        match = False
```

**Удаление** (`delete_records`) делегирует поиск методу `search_records`, затем удаляет найденные объекты из `self.records` через `list.remove()`. Возвращает количество удалённых записей.

## 6. Сценарии демонстрации системы

### Сценарий 1: Запуск приложения

1. Выполнить `python main.py` из директории `warehouse_app/`.
2. Открывается главное окно 1400×750 px с пустой таблицей.
3. Строка состояния отображает «Готов».
4. Счётчик показывает «Всего записей: 0», пагинация — «Страница 1 из 1».

### Сценарий 2: Генерация и просмотр тестовых данных

1. Нажать кнопку «Тестовые данные» на панели инструментов (или меню Данные → Генерировать тестовые данные).
2. В таблице появляются 54 записи; строка состояния: «Сгенерировано 54 тестовых записей».
3. Счётчик: «Всего записей: 54», пагинация: «Страница 1 из 6» (при 10 записях на странице).
4. Нажать «>» — переход на страницу 2. Нажать «>>» — переход на последнюю страницу.
5. В поле Spinbox изменить значение с 10 на 20 — таблица перестраивается, пагинация: «Страница 1 из 3».

### Сценарий 3: Добавление записи

1. Нажать «Добавить» на панели инструментов.
2. Открывается модальный диалог «Добавить запись».
3. Заполнить поля:
   - Название товара: `Тестовый товар`
   - Производитель: `ООО Тест`
   - УНП: `123456789`
   - Количество: `100`
   - Адрес склада: `Минск, ул. Тестовая, 1`
4. Нажать «OK» — диалог закрывается, запись появляется в таблице, пагинация сбрасывается на страницу 1.
5. Попытаться добавить запись с буквами в поле УНП — система выдаёт ошибку «УНП должен содержать только цифры», диалог остаётся открытым.
6. Установить флажок «Нет на складе» — поле количества блокируется. Нажать «OK» — запись сохраняется с `quantity_in_stock = "нет на складе"`.

### Сценарий 4: Поиск записей

1. Нажать «Поиск» на панели инструментов.
2. Открывается немодальный диалог «Поиск записей».
3. **Поиск по производителю:** ввести в поле «Производитель» значение `Bosch`, нажать «Найти».
   - Ожидаемый результат: все записи с `manufacturer_name`, содержащим «Bosch» (нечувствительно к регистру).
4. **Составной поиск:** ввести «Производитель» = `Makita`, «Адрес склада» = `Минск`.
   - Ожидаемый результат: только записи Makita, расположенные на складах в Минске (AND между группами).
5. **Поиск по количеству:** ввести «Количество» = `нет на складе`.
   - Ожидаемый результат: все записи с отсутствующим товаром.
6. Результаты отображаются с пагинацией; счётчик «Найдено: N» обновляется после каждого поиска.

### Сценарий 5: Удаление записей

1. Нажать «Удалить» на панели инструментов.
2. Открывается модальный диалог «Удаление записей (Вариант 6)».
3. Ввести «Производитель» = `Patriot`, нажать «Удалить».
4. Система удаляет все записи с производителем Patriot, показывает «Удалено записей: 2».
5. Главная таблица обновляется, пагинация сбрасывается на страницу 1.
6. Попытка нажать «Удалить» с пустыми полями — система выдаёт предупреждение «Укажите хотя бы один критерий для удаления».

### Сценарий 6: Сохранение и загрузка XML

1. Меню Файл → Сохранить (или кнопка «Сохранить»).
2. Открывается стандартный диалог сохранения файла с фильтром `*.xml`.
3. Указать путь, нажать «Сохранить» — файл записывается в UTF-8 с отступами.
4. Меню Файл → Новый — таблица очищается, счётчик обнуляется.
5. Меню Файл → Открыть — выбрать сохранённый файл.
6. Данные загружаются через SAX-парсер; строка состояния: «Загружено из <путь>».
7. Таблица отображает загруженные записи, пагинация сбрасывается на страницу 1.

## 8. Заключение

В ходе лабораторной работы разработано приложение управления складскими товарами на Python с использованием архитектуры MVC и пассивной модели. Чёткое разделение ответственности между компонентами обеспечивает независимость бизнес-логики от деталей представления: модель не зависит от tkinter и может быть протестирована изолированно. Применение SAX для чтения и DOM для записи XML демонстрирует обоснованный выбор инструмента под конкретную задачу. Реализованная логика поиска и удаления по составным критериям Варианта 6 (OR внутри групп, AND между группами) обеспечивает гибкую фильтрацию данных при минимальной сложностью алгоритма.
